(see `.claude/docs/config-resolution.md`).

## Collaboration Protocol

**User-driven collaboration, not autonomous execution.**
Every task follows: **Question -> Options -> Decision -> Draft -> Approval**

- Agents MUST ask "May I write this to [filepath]?" before using Write/Edit tools
  (exempt: `active.md` appends, agent memory, a subagent's new file at the path
  its orchestrating skill named; see `.claude/rules/agent-memory.md`)
- Agents MUST show drafts or summaries before requesting approval
- Multi-file changes require explicit approval for the full changeset
- No commits without user instruction
- A skipped or dismissed question is not an answer: act on nothing, re-ask in
  plain text and wait
- Started outside this file's folder? Warn first: hooks, deny rules and the
  ask-first mode load only when Claude Code starts here

See `docs/COLLABORATIVE-DESIGN-PRINCIPLE.md` for full protocol and examples.

> **First session?** If the project has no engine configured and no game concept,
> run `/start` to begin the guided onboarding flow.

## Context Management

Read `.claude/docs/context-management.md` on demand — it is a reference, not
session context. Two of its conventions are load-bearing and cited by name
elsewhere in the repo, so they are restated here rather than lost:

- **`production/session-state/active.md` is the session checkpoint.** The file is
  the memory, not the conversation. Read it first after any compaction, crash, or
  `/clear`.
- **Helpers in `.claude/scripts/` emit observations, never verdicts.** A script
  that scores or judges will eventually contradict a mode or override it cannot
  see. (Cited by `artifact-check.sh` and `adr-dep-graph.sh`.)

## Herramientas instaladas: cuándo usar cada una

**Claude Code Game Studios (CCGS)** — agentes y skills en `.claude/` (`/setup-engine`, etc.).
Úsalo para: planificar y diseñar el juego (GDD, pilares, sistemas), arquitectura,
sprints, revisión de código, QA y playtests. Para trabajo de Godot, usa los
agentes especialistas de Godot. Elige Godot 4 / GDScript en `/setup-engine`.

**Glade MCP (`gladekit-mcp`, ver `.mcp.json`)** — conecta con el editor de Godot abierto.
Úsalo para: crear/editar escenas, nodos, scripts y recursos EN el editor, tomar
capturas del juego (`look_at_game_view`) y verificar que funciona. Solo funciona si
el editor está abierto con el addon activo: copia
`tools/glade-godot-bridge/addons/com.gladekit.mcp-bridge/` a `<proyecto-godot>/addons/`
y actívalo en Project Settings → Plugins. Si no hay editor, no insistas: edita
los archivos `.gd`/`.tscn` directamente.

Regla de oro: CCGS decide *qué* y *cómo* se construye; Glade lo ejecuta en el editor.
